## Bugs and gaps for the main app owner

1. **Approved additional rest can be placed entirely inside the protected break** (`PATCH /api/rest-requests/:id`, `action: "approve"`). The API accepts an interval that overlaps the worker's own protected break, so "additional" rest can add no rest at all. PROJECT_SPEC says approval "creates separate additional rest". The UI places rest after the protected break, but the API does not enforce it. Repro: `tests/integration/api-invariants.spec.ts`, "approved additional rest must not be absorbed inside the protected break" (`test.fixme`; it returns 200 where 409 is expected). Suggested rule: reject approval intervals that overlap a protected break of the same worker, or document the intended semantics.
2. **Hosted secrets are read from the environment, not config overrides** (`loadConfig`). `createApp({ hosted: true })` throws unless `COOKIE_SECRET`/`MEASUREMENT_TOKEN` are set in `process.env`, even when overrides supply them. This is low severity and only affects tests and embedding.
3. **Playwright/browser version coupling.** `@playwright/test@^1.58.0` resolved to 1.64, which needs a fresh browser download. Offline or preinstalled-browser environments fail `npm run test:e2e`. Option: pin the Playwright version to match the team's installed browsers.
